# Search discovery plan

Use the Search Console URL-prefix property for the live site as the measurement source. The intent examples below are hypotheses, not verified search volumes or rankings. Review real queries and pages before expanding them. Google results and generative answers cannot be guaranteed.

| Searcher task | Existing destination or action | Evidence to track |
| --- | --- | --- |
| Make a film or video with Codex | Bilingual film-making guide; links from both homepages | Impressions, clicks and indexed status for each language |
| Make a whiteboard explainer | Whiteboard style guide and public-input case | Query and landing page impressions; indexed canonical |
| Choose a visual style | Style library and individual style guides | Non-brand queries and landing pages by style |
| Install the film kit or plugin | Linked installation guide, actual pinned plugin version | Installation-related queries; broken-link checks |
| Add narration, captions and music | Narration and production methods linked from tutorial | Relevant query impressions; outbound method-guide visits where analytics exists |
| Rebuild a sample | Case walkthrough and per-style capability notes | Indexed case pages; queries about examples and reproduction |
| Deliver editable video projects | Tutorial and production workflow | Queries for editable project, rendering and MP4 delivery |

## Execution and measurement

1. Resolve the Search Console sitemap processing error before assuming it aids discovery. Live URL inspection and successful submission do not prove sitemap processing. Check Google-selected canonicals and the Pages report for the new guide after deployment; request indexing only when appropriate.
2. Keep navigation and contextual links crawlable in initial HTML, with meaningful anchor text. Keep en/zh-CN reciprocal alternates and self-canonical URLs, and include only public indexable pages in the sitemap.
3. Build a weekly baseline from Search Console: dates and report delay, clicks, impressions, CTR and average position, split by query, landing page and country. Compare matched date ranges and record domain migrations or releases. Do not interpret a single impression as a stable rank or calculate growth from a zero baseline.
4. Improve pages based on observed questions and actual production evidence. Add a dedicated page only when it gives a distinct, complete answer and has a maintained source; avoid near-duplicate keyword pages.
5. For AI discovery, use the same accessible pages, accurate descriptions, structured relationships and source-backed evidence. Periodically test a fixed set of non-leading questions in named products, recording date, locale, query, model/product and cited URLs. This is a small qualitative sample, not a platform-wide citation rate.
6. Share or update links only in relevant owned profiles and existing documentation. Do not fabricate mentions, reviews or outreach. Obtain explicit authorization before posting or messaging others.

Official guidance: https://developers.google.com/search/docs/fundamentals/creating-helpful-content and https://developers.google.com/search/docs/fundamentals/ai-optimization-guide . HowTo rich results are discontinued and FAQ rich results are restricted; adding markup is not a promise of a rich result.
